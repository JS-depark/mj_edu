# 차곡 · 마작 퍼즐

아이폰 세로 화면과 한 손 조작을 살펴보기 위한 초기 웹게임입니다. 외부 라이브러리나 빌드 과정 없이 HTML, CSS, JavaScript로 실행됩니다.

## 실행

Node.js 20 이상에서 `npm start`를 실행하고 `http://127.0.0.1:4173`을 엽니다. 개발 서버는 이 PC 내부 주소인 `127.0.0.1`에서만 연결을 받습니다. 같은 Wi-Fi의 휴대폰이나 다른 PC에서는 접속할 수 없습니다. 아이폰 테스트는 GitHub Pages 등에 별도로 배포한 주소로 진행할 수 있습니다.

## 들어 있는 기능

- 몸통 두 개 만들기 → 네 몸통과 머리 → 자패 익히기 → 탕야오의 네 단계. 모든 단계에 바로 접근할 수 있습니다.
- 매번 새로 섞는 유한 패산, 각 패는 정확히 네 장입니다. 첫 두 단계는 만수 36장, 자패 단계는 동·남·서·북·백·발·중 28장, 탕야오는 만·통·삭 108장으로 연습합니다. 34종 136장 생성도 지원하며, 전체 패산을 사용하는 역 스테이지는 별도 설계 예정입니다.
- 공급대 13자리. 2장 머리 또는 3장 몸통을 등록한 후 직접 공급 버튼으로 빈자리를 채웁니다.
- 자패는 같은 패로만 커쯔·머리를 만들 수 있습니다. 자패 연습에서는 커쯔 두 개를 만들며 도움말에 일곱 자패의 그림과 이름을 표시합니다. 자패에는 숫자 도움 표시를 붙이지 않습니다.
- 한 장 버리고 한 장 쯔모하기. 버림패는 순서를 유지하며 패산에 다시 넣지 않습니다. 작업대와 공급대 사이의 여유 공간에 여러 줄로 펼칩니다. 공간을 넘으면 순번 범위를 표시하고 이전/다음 버튼으로 넘깁니다. 기록을 생략하거나 스크롤로 숨기지 않습니다.
- 자동정렬은 기본값이 꺼져 있습니다. 꺼져 있으면 새 패는 기존 빈자리 또는 버린 패의 위치에 들어가며 정렬 버튼으로만 다시 정렬합니다. 켜면 즉시 정렬하고 이후 등록·공급·한 장 교체·재조립 완료 뒤에 정렬합니다. 패 선택 중과 재조립 중에는 위치를 유지합니다. 설정은 브라우저에 저장합니다.
- 재조립은 시작할 때의 몸통 수, 머리 유무, 공급대 패 수를 모두 복구해야 끝납니다. 재조립 중에는 공급과 버림이 불가능하며 취소하면 원상복구합니다.
- 마지막 패를 공급한 뒤 조합 등록과 재조립을 마칠 기회를 줍니다. 목표 완성 시 즉시 클리어, 미완성 상태에서는 ‘이번 판 마치기’로 실패를 확정합니다. 패산이 비면 더 뽑을 수 없습니다.
- 공급대는 7열의 2줄로 고정합니다. 숫자 도움 표시, 모양 설명과 한 묶음 힌트를 제공합니다. 게임 이름의 별도 상단 줄은 없애고 도움말과 설정은 단계 제목 옆 메뉴에 모았습니다.
- 작업대 내부 스크롤을 없애고 실제 표시 영역 높이에 맞춰 배치합니다. 아주 낮은 화면이나 확대된 글자에서는 내용을 자르지 않고 페이지 스크롤을 허용합니다.
- 재조립과 도움말은 모바일 화면 전체를 쓰며 하단 버튼이 고정됩니다. 재조립에서 원래 차 있던 슬롯은 비워도 강조되며 ‘다시 채우기’로 표시됩니다. 처음부터 비어 있던 슬롯은 회색의 ‘사용 안 함’으로 구분합니다. 재등록은 강조된 슬롯만 채웁니다.
- 재조립할 패가 많으면 최대 4줄로 표시하고, 공간에 따라 패 높이를 조정합니다. 매우 낮은 화면에서는 패 영역만 스크롤할 수 있습니다.
- 클리어와 실패 결과는 모바일 전체 높이를 사용합니다. 완성 패, 점수 구성, 보너스와 기록을 간결하게 표시하고 재도전/다음 단계 버튼을 하단에 고정합니다. 보너스 이름을 누르면 별도 설명 화면으로 이동하며 결과 화면으로 돌아올 수 있습니다.
- 현재 판, 설정, 완료 단계, 최고 기록을 기기의 브라우저에 저장합니다. 재조립 중 새로고침하면 재조립 직전 상태로 복구합니다. 브라우저 데이터 삭제 시 기록도 삭제됩니다.

## 점수와 범위

앞의 세 단계는 무점수 연습입니다. 탕야오는 클리어 1,000점 + 남은 패 한 장당 10점 + 추가 모양 보너스를 줍니다. 이페코 150, 량페코 300, 또이또이 250, 청일색 300, 삼색동순 200점이며 이페코/량페코는 동시에 지급하지 않습니다. 점수 계수는 아직 밸런싱하지 않은 초기값입니다.

보너스는 **플레이어가 작업대에 등록한 분해**에서 확인되는 구조만 평가합니다. 모든 가능한 분해 중 최고 점수를 탐색하지 않습니다. 실제 화료나 멘젠 상태가 없는 퍼즐이므로 ‘역의 모양’으로 설명하며, 리치/멘젠쯔모/핑후/삼암각/사암각 등 상황 판정이 필요한 역은 평가하지 않습니다. 실전 점수 계산기가 아닙니다.

타가, 치·펑·깡·론, 후리텐, 실전 손패 전환은 아직 구현하지 않았습니다. 자동 플레이 시뮬레이션이나 백분위도 아직 제공하지 않습니다. 공급 횟수, 한 장 교체 횟수와 최장 연속 교체 횟수는 상태에 기록합니다.

## GitHub Pages

이 폴더를 GitHub 저장소에 올리고 **Settings → Pages → Deploy from a branch → main → /(root)** 로 지정하면 됩니다. `index.html`과 그 파일이 참조하는 `styles.css`, `app.js`, `engine.js`, `favicon.svg`, `assets/tiles/`가 같은 상대 경로를 유지해야 합니다. 하위 프로젝트 주소에서도 실행되도록 경로는 상대 경로를 사용했습니다. `.nojekyll`을 포함합니다. 이 작업에서는 원격 저장소 생성이나 인터넷 배포를 수행하지 않았습니다.

아이폰에서는 배포된 사이트를 Safari의 공유 메뉴에서 ‘홈 화면에 추가’한 뒤 홈 화면 아이콘으로 실행하면 브라우저 도구 막대가 없는 웹앱으로 테스트할 수 있습니다. ‘웹 앱으로 열기’ 옵션이 표시되면 켜 두세요. 이 방식은 앱스토어용 앱 빌드나 오프라인 캐시 구현과는 별개입니다.

## 검증

`npm test`로 패 보존, 등록/공급, 재조립 불변 조건, 마지막 패, 보너스 중복 등을 확인할 수 있습니다. 실제 아이폰의 Safari와 홈 화면 웹앱에서의 조작 검증은 별도로 필요합니다.

2026-09-22 화면 수정 후 자동 테스트 12개가 통과했습니다. PC 브라우저의 375×600 및 375×568 표시 영역에서 작업대와 공급대가 페이지 스크롤 없이 보이는 것을 확인했습니다. 375×568에서도 몸통 네 개를 모두 풀어 25장이 된 재조립 화면은 패 영역 스크롤 없이 표시됐으며, 패 버튼 크기는 약 46×60px였습니다. 슬롯 강조 유지, 재등록 후 완료 활성화, 취소 복원과 도움말의 하단 버튼도 확인했습니다. 이는 아이폰 Safari 자체의 검증을 대체하지 않습니다.

추가 수정에서는 375×568에서 튜토리얼 클리어, 량페코+청일색 보너스 결과, 실패 결과 및 게임 메뉴에 스크롤이 없는 것을 확인했습니다. 버림패 36장은 375×812에서 한꺼번에 표시되며, 95장의 기록도 작은 화면에서 페이지를 넘겨 누락 없이 확인했습니다. 높이 568/600/601/667/731에서 메인 화면의 세로 넘침이 없었습니다. 자동정렬의 기본 꺼짐, 켰을 때 등록·공급·교체 후 정렬, 선택/재조립 중 위치 보존, 새로고침 후 설정 유지도 확인했습니다.

결과 화면 등 특정 상태는 `node scripts/preview-fixtures.mjs`로 별도 로컬 미리보기를 실행하여 재현할 수 있습니다. `http://127.0.0.1:4174/?case=bonus`에서 `bonus`, `tutorial`, `river`, `lost`, `sort`를 선택합니다. 이 주소는 테스트 저장 상태를 초기화하며, 일반 게임 서버와 다른 출처를 사용해 실제 연습 기록에 영향을 주지 않습니다. 테스트 서버도 같은 Wi-Fi에 공개되지 않습니다.

## 다음 개발 순서 제안

역 스테이지 설계가 먼저입니다. [역 후보 12종과 커리큘럼 초안](YAKU_STAGE_PLAN.md)에 채택/보류 범위, 복합 목표, 기록과 자동 플레이의 선행 조건, 네 사람의 버림패 영역을 정리했습니다. 아래 반복 플레이·통계 계획은 이 설계의 초기 범위를 정한 뒤 진행합니다.

1. 정해진 초기 역 스테이지로 반복 플레이하며 선택의 재미, 한 판 길이, 막혀서 한 장 교체만 반복하는 구간을 확인합니다.
2. 도전 횟수·완료/실패·점수·공급/교체·재조립·발견한 모양과 난수 시드, 규칙/점수 버전을 판별로 기록합니다. 평균 점수는 클리어 판 기준임을 표시하고 클리어율은 별도로 보여줍니다. 중도 재시작도 별도 집계합니다.
3. 등록 가능한 묶음 우선, 정해진 공급 규칙, 무작위 타패를 쓰는 기준 자동 플레이를 구현합니다. 같은 규칙·점수 버전으로 시뮬레이션하고 클리어율, 남은 패, 교체 횟수 분포를 분석합니다. 비교 순위는 사람의 순위가 아닌 ‘기준 자동 플레이 대비’임을 명확히 표시합니다.
4. 게임 메뉴의 기록 페이지와 발견한 역 도감을 연결하고, 단일 역에서 복합 역으로 넘어가는 소수의 스테이지를 추가합니다.
5. 선택·타패·공급 효과음과 음량/끄기 옵션을 추가합니다. 타가 버림패와 실전 전환은 이 과정의 재미를 검증한 뒤 확장합니다.

## 패 이미지

[FluffyStuff / riichi-mahjong-tiles](https://github.com/FluffyStuff/riichi-mahjong-tiles)의 Regular SVG를 수정 없이 사용합니다. 원본 저장소의 라이선스는 [CC0 / public domain](https://creativecommons.org/publicdomain/zero/1.0/)이며 사본은 `assets/tiles/LICENSE.md`에 있습니다.

상업적 이용을 허용하는 CC0 원본 선언, 자패 그림을 가져온 리비전과 파일 해시는 [출처 기록](assets/tiles/SOURCES.md)에 남겼습니다. 메뉴의 출처 표기도 유지합니다.

자패 추가 후 테스트 15개가 통과했으며, 여기에는 네 단계의 240회 기계적 플레이에 대한 패 보존 검사와 자패의 슌쯔 금지 검사가 포함됩니다. PC 브라우저의 375×568 화면에서 네 단계 목록과 자패 도움말이 스크롤 없이 보이고, 모든 자패 그림이 로드되며 등록·공급·클리어가 동작하는 것을 확인했습니다. 실물 아이폰에서의 추가 확인은 필요합니다.
