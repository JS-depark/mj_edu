# 차곡 · 마작 퍼즐

아이폰 세로 화면과 한 손 조작을 살펴보기 위한 초기 웹게임입니다. 외부 라이브러리나 빌드 과정 없이 HTML, CSS, JavaScript로 실행됩니다.

## 실행

Node.js 20 이상에서 `npm start`를 실행하고 `http://127.0.0.1:4173`을 엽니다. 개발 서버는 이 PC 내부 주소인 `127.0.0.1`에서만 연결을 받습니다. 같은 Wi-Fi의 휴대폰이나 다른 PC에서는 접속할 수 없습니다. 아이폰 테스트는 GitHub Pages 등에 별도로 배포한 주소로 진행할 수 있습니다.

## 들어 있는 기능

- 처음 실행하면 만수·삭수·통수 1~9를 보여주고, 다음 페이지에서 동남서북·백발중을 소개합니다. 게임 메뉴에서 언제든 다시 볼 수 있습니다.
- 무점수 기초 6단계: 슌쯔 2개 → 커쯔 2개 → 자패 커쯔 2개 → 몸통 2개와 머리 → 세 무늬로 몸통 2개와 머리 → 몸통 4개와 머리. 이후 탕야오·이페코·또이또이·청일색·혼일색·일기통관·삼색동순·찬타·준찬타·혼노두·삼색동각·량페코 12개 역을 플레이하며 점수를 기록합니다. 각 단계 첫 진입에 예시와 짧은 목표 안내를 표시합니다. 같은 단계 재도전은 바로 시작하고, 역 단계에서는 놀이 방법의 ‘목표 설명’으로 다시 볼 수 있습니다. 단계 선택은 기초 두 페이지와 역 세 페이지이며 모든 단계에 바로 접근할 수 있습니다. 역의 순서는 난도 확정 순서가 아닙니다.
- 매번 새로 섞는 유한 패산, 각 패는 정확히 네 장입니다. 기초 1·2·4·6은 만수 36장, 기초 3은 자패 28장, 기초 5는 수패 108장, 열두 역은 모두 자패를 포함한 136장으로 연습합니다. 청일색도 세 무늬 중 모을 무늬를 직접 고릅니다. 슌쯔·커쯔 첫 연습은 해당 종류만 등록할 수 있습니다. 각 역의 목표와 추가 역을 같은 판정기로 확인합니다.
- 공급대 13자리. 2장 머리 또는 3장 몸통을 등록한 후 직접 공급 버튼으로 빈자리를 채웁니다.
- 자패는 같은 패로만 커쯔·머리를 만들 수 있습니다. 자패 연습에서는 커쯔 두 개를 만들며 도움말에 일곱 자패의 그림과 이름을 표시합니다. 자패에는 숫자 도움 표시를 붙이지 않습니다.
- 한 장 버리고 한 장 쯔모하기. 버림패는 순서를 유지하며 패산에 다시 넣지 않습니다. 혼자 연습할 때는 네 줄 × 열 장, 한 페이지 40장으로 고정합니다. 41번째부터 다음 페이지로 넘어가며 화면 높이가 바뀌어도 보고 있던 페이지를 유지합니다. 향후 타가 도입 시 나·하가·대가·상가에 한 줄씩 배정하고 각 줄의 가로 스크롤을 허용할 계획입니다.
- 자동정렬은 기본값이 꺼져 있습니다. 꺼져 있으면 새 패는 기존 빈자리 또는 버린 패의 위치에 들어가며 정렬 버튼으로만 다시 정렬합니다. 켜면 즉시 정렬하고 이후 등록·공급·한 장 교체·재조립 완료 뒤에 정렬합니다. 패 선택 중과 재조립 중에는 위치를 유지합니다. 설정은 브라우저에 저장합니다.
- 재조립은 시작할 때의 몸통 수, 머리 유무, 공급대 패 수를 모두 복구해야 끝납니다. 재조립 중에는 공급과 버림이 불가능하며 취소하면 원상복구합니다.
- 새 역 단계는 올바른 몸통·머리라면 등록할 수 있지만, 슬롯을 모두 채워도 목표 역이 없으면 ‘역 미완성’으로 표시합니다. 교체·공급·재조립으로 계속 플레이하며, 등록 또는 재조립 완료 시 목표를 확인합니다. 재조립 중 잠시 목표가 만들어져도 완료를 눌러야 클리어합니다. 목표가 없는 가득 찬 작업대도 저장하고 이어 할 수 있습니다. 기존 탕야오의 1·9 등록 제한은 유지합니다.
- 마지막 패를 공급한 뒤 조합 등록과 재조립을 마칠 기회를 줍니다. 목표 완성 시 즉시 클리어, 미완성 상태에서는 ‘이번 판 마치기’로 실패를 확정합니다. 패산이 비면 더 뽑을 수 없습니다.
- 공급대는 7열의 2줄로 고정합니다. 패 13자리와 마지막 칸의 정렬/선택 취소 버튼으로 구성하며 보관 가능한 패 수는 13장입니다. 숫자 도움 표시, 모양 설명과 한 묶음 힌트를 제공합니다. 게임 이름의 별도 상단 줄은 없애고 도움말과 설정은 단계 제목 옆 메뉴에 모았습니다.
- 목표 설명·작업대·공급대의 높이는 같은 화면 크기에서 고정합니다. 설명 길이·묶음 수·선택 상태가 버림패 네 줄의 공간을 줄이지 않습니다. 실제 너비와 안전 영역을 제외한 높이로 패·칸 크기를 함께 계산하며, 남는 높이를 버림패 아래의 빈 공간으로 두지 않습니다. 버림패는 가로 3 : 세로 4 비율을 유지합니다. 두 줄 작업대를 기본으로 하며, 내용 영역이 605px 미만인 짧은 화면에서만 한 줄로 표시합니다. 이전의 699px CSS 컨테이너 분기 대신 같은 크기 계산을 사용합니다. 공급대의 패와 정렬/취소 버튼은 최소 44px 높이를 유지합니다. 작업대 내부 스크롤은 없으며 지원 높이보다 매우 낮은 화면에서는 내용을 자르지 않고 페이지 스크롤을 허용합니다.
- 재조립과 도움말은 모바일 화면 전체를 쓰며 하단 버튼이 고정됩니다. 재조립에서 원래 차 있던 슬롯은 비워도 강조되며 ‘다시 채우기’로 표시됩니다. 처음부터 비어 있던 슬롯은 회색의 ‘사용 안 함’으로 구분합니다. 재등록은 강조된 슬롯만 채웁니다.
- 재조립할 패가 많으면 최대 4줄로 표시하고, 공간에 따라 패 높이를 조정합니다. 매우 낮은 화면에서는 패 영역만 스크롤할 수 있습니다.
- 클리어와 실패 결과는 모바일 전체 높이를 사용합니다. 몸통 칸을 작업대보다 높게 만들고, 여유가 있는 화면에서는 추가 모양을 설명 카드로 펼칩니다. 짧은 화면에서는 간결한 카드로 표시합니다. 실제 결과 영역 높이를 기준으로 배치를 조정해 상하 안전 영역도 고려합니다. 재도전/다음 단계 버튼은 하단에 고정합니다. 보너스를 누르면 해당 모양과 판수 ×100 계산을 설명합니다.
- 현재 판, 설정, 완료 단계, 점수 버전별 최고 기록을 브라우저에 저장합니다. 이전 최고 기록과 옛 ‘몸통 만들기’ 진행도 보존합니다. 옛 점수는 현재 점수와 비교하지 않습니다. 재조립 중 새로고침하면 재조립 직전 상태로 복구합니다. 브라우저 데이터 삭제 시 기록도 삭제됩니다.

## 점수와 범위

앞의 여섯 단계는 무점수 연습입니다. 점수 규칙 v4는 **목표 역 판수 × 100 + 남은 패 × 10 + 추가 역 판수 합 × 100**입니다. 열두 역 모두 목표와 보너스로 판정합니다. 목표 역은 중복 가산하지 않습니다. 이페코 목표에서 량페코를 만들면 목표는 량페코 3판/300점으로 대체하며 이페코를 따로 더하지 않습니다. 혼일색/청일색, 찬타/준찬타도 중복 계산하지 않고, 혼노두와 또이또이처럼 함께 성립하는 역은 각각 인정합니다.

클리어하면 같은 역의 **기준 자동 플레이 대비 상위 비율**과 별을 보여줍니다. 클리어 1개, 상위 50% 이내 2개, 상위 10% 이내 3개입니다. 다음 별까지 필요한 점수도 표시합니다. 순위 부분을 누르면 표본 수와 별 기준 점수를 볼 수 있습니다. 단계 선택에는 현재 규칙의 최고점·별·순위를 표시합니다.

기준은 136장으로 각 역마다 10,000판씩 실행한 조합 보존 자동 플레이이며, 클리어한 기록만 비교합니다. 실패는 0점으로 섞지 않고 동점은 중간 순위로 계산합니다. 사람들의 순위나 실전 난도를 의미하지 않습니다. 게임에는 약 15KB의 점수별 빈도 집계만 포함하고 실험 코드와 개별 판 데이터는 별도 폴더에 그대로 둡니다. 출처·동점 공식·별 기준은 [비교 기준 문서](BENCHMARK.md)에 있습니다.

이전 108장 저장 판은 원래 패와 점수 v3로 계속 플레이하며 새 순위·별에서는 제외합니다. 새 판부터 136장과 v4를 적용합니다. 최고점은 점수 버전별, 별은 비교 기준별로 보존하며 과거 점수를 새 점수와 비교하지 않습니다.

보너스는 **플레이어가 작업대에 등록한 분해**에서 확인되는 구조만 평가합니다. 모든 가능한 분해 중 최고 점수를 탐색하지 않습니다. 실제 화료나 멘젠 상태가 없는 퍼즐이므로 ‘역의 모양’으로 설명하며, 리치/멘젠쯔모/핑후/삼암각/사암각 등 상황 판정이 필요한 역은 평가하지 않습니다. 실전 점수 계산기가 아닙니다.

타가, 치·펑·깡·론, 후리텐, 실전 손패 전환은 아직 구현하지 않았습니다. 백분위는 외부 시뮬레이션의 집계만 사용하며 게임 안에서 자동 플레이를 실행하지 않습니다. 공급 횟수, 한 장 교체 횟수와 최장 연속 교체 횟수는 상태에 기록합니다.

## GitHub Pages

이 폴더를 GitHub 저장소에 올리고 **Settings → Pages → Deploy from a branch → main → /(root)** 로 지정하면 됩니다. `index.html`과 그 파일이 참조하는 `styles.css`, `app.js`, `engine.js`, `benchmark.js`, `benchmark-data.js`, `favicon.svg`, `assets/tiles/`가 같은 상대 경로를 유지해야 합니다. 하위 프로젝트 주소에서도 실행되도록 경로는 상대 경로를 사용했습니다. `.nojekyll`을 포함합니다. 이 작업에서는 원격 저장소 생성이나 인터넷 배포를 수행하지 않았습니다.

아이폰에서는 배포된 사이트를 Safari의 공유 메뉴에서 ‘홈 화면에 추가’한 뒤 홈 화면 아이콘으로 실행하면 브라우저 도구 막대가 없는 웹앱으로 테스트할 수 있습니다. ‘웹 앱으로 열기’ 옵션이 표시되면 켜 두세요. 이 방식은 앱스토어용 앱 빌드나 오프라인 캐시 구현과는 별개입니다.

## 검증

`npm test`로 패 보존, 등록/공급, 재조립 불변 조건, 마지막 패, 보너스 중복 등을 확인할 수 있습니다. 실제 아이폰의 Safari와 홈 화면 웹앱에서의 조작 검증은 별도로 필요합니다.

이전 네 역 구현 시 자동 테스트 23개가 통과했습니다. 10단계의 600회 기계적 플레이로 패 보존을 확인하고, 새 역 목표별 성공/미완성, 저장 복원 가능 여부, 마지막 패 이후 재조립 성공, 목표 모양의 보너스 제외와 ×100 계산을 검사합니다. 이 테스트는 목표 지향 봇이나 12개 역 스테이지의 난도 시뮬레이션이 아닙니다.

PC 브라우저의 375px 폭과 높이 568/731/812에서 네 역과 상위 모양의 클리어 결과에 세로 넘침이 없는 것을 확인했습니다. 375×568에서 네 역을 한 페이지에서 선택할 수 있고, 새 역 안내와 목표 설명 다시 보기도 스크롤 없이 표시됩니다. 청일색에서 다른 무늬의 머리가 남으면 ‘역 미완성’으로 계속 플레이하고, 머리를 재조립해 완료하면 클리어되는 것을 직접 확인했습니다. 이전 점수 9,990점과 v2 최고 8,880점이 있는 테스트에서도 당시 최고는 v3 기준 2,510점으로 표시되었습니다. 실제 아이폰 Safari 및 홈 화면 웹앱의 추가 확인은 필요합니다.

버림패 배치 재수정 후 375×568, 375×761(위 47px·아래 34px 여백), 414×736에서 각각 10개 단계 모두 같은 버림패·공급대 위치와 설명 넘침 없음을 확인했습니다. 375px 폭의 높이 540/568/624/625/667/731/812와 414×736에서 네 줄 40장, 패의 3:4 비율, 최소 44px 공급대 터치 높이, 페이지 스크롤 없음을 확인했습니다. 네 번째 버림패 줄과 공급대 영역 사이는 5~6px이며 이전 페이지를 보고 크기를 바꿔도 페이지가 유지됩니다. 375×568의 아래 34px 여백과 375×812의 위 47px·아래 34px 여백도 별도로 확인했습니다. 사진과 비슷한 두 홈 화면 크기에서는 작업대를 두 줄로 표시합니다. 이 검증은 PC 브라우저의 화면 크기 및 여백 모사이며 실제 iOS Safari 검증을 대신하지 않습니다.

결과 화면 등 특정 상태는 `node scripts/preview-fixtures.mjs`로 별도 로컬 미리보기를 실행하여 재현할 수 있습니다. `http://127.0.0.1:4174/?case=bonus`의 `case`는 `bonus`, `tutorial`, `river`, `river40`, `river41`, `lost`, `sort`, `honors`, `intro`, `pairs`, `oldscore`, `sequence`, `triplet`, `lessons`, `iipeikou`, `toitoi`, `chinitsu`, `upgrade`, `pending_iipeikou`, `pending_toitoi`, `pending_chinitsu` 또는 `layout_단계ID`입니다. `&safe=home`은 위 47px·아래 34px, `&safe=bottom`은 아래 34px 안전 여백을 모사합니다. 이 주소는 테스트 저장 상태를 초기화하며, 일반 게임 서버와 다른 출처를 사용해 실제 연습 기록에 영향을 주지 않습니다. 쿼리 없는 `/`로 이동하면 초기화하지 않고 현재 상태를 유지합니다. 테스트 서버도 같은 Wi-Fi에 공개되지 않습니다.

## 이번 검증과 다음 범위

32개 규칙 테스트는 18단계의 1,080회 패 보존 플레이, 12개 목표, 역 중복·점수, 이전 저장 복원, 백분위·동점·별 경계를 확인합니다. 순위 원본 120,000판 중 클리어 118,181판의 역·점수를 현재 엔진과 대조하여 전부 일치함을 확인했습니다. 규칙 테스트와 순위용 시뮬레이션은 별개입니다.

최신 UI는 PC 브라우저에서 375×568, 375×761(상단 47px·하단 34px 여백), 414×736으로 열두 역 결과·순위 설명·목표 설명·단계 다섯 페이지와 실제 머리 등록 후 클리어/저장 복원을 검사했습니다. 넘침이 있었던 큰 결과 화면을 수정한 뒤 보너스 두 개와 이전 규칙 결과를 375×667/812, 430×932 및 안전 여백을 포함한 일곱 화면 조건에서 다시 확인했습니다. 결과·순위/추가 역 상세에 세로 넘침이 없고, 낮은 점수로 재도전해도 기존 최고점과 별이 유지되는 것을 확인했습니다. 실제 아이폰 검증은 별도로 필요합니다.

미리보기에는 `result_역ID`, `finish_역ID`, `maxbonus`, `legacy`를 추가했습니다. `finish_역ID`는 머리를 등록하면 클리어되는 상태입니다. `&safe=home` 여백은 보드와 대화창 모두에 적용합니다. 일반 서버를 이전부터 켜 두었다면 새 파일 경로를 제공하도록 다시 시작해야 합니다.

다음에는 실제 플레이로 역별 별 획득률, 반복 교체 부담과 재조립의 재미를 확인합니다. 번호는 잠정이며 별 자체가 역 사이의 실전 난도를 뜻하지 않습니다. 상세 도전 기록·역 도감, 복합 역 미션, 효과음, 타가 버림패와 실전 전환은 이후 범위입니다. 이번 변경에서는 커밋·푸시·인터넷 배포를 하지 않았습니다.
